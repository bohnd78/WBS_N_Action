## 2. 헤더 KPI 대시보드

앱 상단에 항상 표시되는 7개 주요 지표입니다.

| KPI 카드 | 설명 |
|----------|------|
| 📋 WBS 총계 | 전체 WBS 항목 수 |

## 3. 📋 WBS 관리 탭

### 3-1. WBS 계층 구조 이해

WBS(Work Breakdown Structure)는 트리 구조로 관리됩니다.

```
📂 Main WBS (루트, Level 1)          ← wbs_code: 1.0
  └ 📁 Sub WBS (Level 2)             ← wbs_code: 1.1
      └ 📄 Sub WBS (Level 3)         ← wbs_code: 1.1.1
          └ 📄 Sub WBS (Level 4)     ← wbs_code: 1.1.1.1
```

- **MAIN 뱃지**: 루트(Level 1) WBS에 표시
- **왼쪽 컬러 바**: 레벨별 색상 구분 (보라→파란→청록→초록)
- **진척률 바**: 각 WBS 아래 표시, 레벨별 색상 일치
- **Action 연결 수**: `🔗 완료/전체` 형식으로 우측 표시

### 3-2. WBS 조회 및 필터

화면 상단 툴바에서 검색과 필터를 사용할 수 있습니다.

| 기능 | 설명 |
|------|------|
| 🔍 검색 | WBS 유형명, 내용에서 키워드 검색. 매칭 항목과 그 **조상 노드**까지 함께 표시 |
| 상태 필터 | 예정/실행중/완료/취소 중 선택하여 필터링 |

### 3-3. WBS 추가

#### 루트 WBS 추가

1. 우측 **➕ 루트 WBS** 버튼 클릭
2. 폼이 화면에 나타나면 정보 입력:
   - **WBS 코드**: 예) `1.0`, `2.0` (선택, 계층 자동 탐색에 사용)
   - **카테고리**: 드롭다운에서 선택 (Admin 탭에서 관리)
   - **항목 유형**: 카테고리 선택 후 연동 드롭다운에서 선택
   - **담당자**: 이름 입력
   - **내용**: 상세 업무 내용
   - **시작일 / 종료예정일 / 종료일**: 날짜 선택
   - **일정 상태**: 예정/실행중/완료/취소
   - **진척률(%) 수동**: 0~100 슬라이더 (자동 계산과 별개)
3. **💾 저장** 클릭

#### Sub WBS (하위 WBS) 추가

1. 부모 WBS 카드의 **➕** 버튼 클릭
2. 상위 WBS가 자동 선택된 폼 표시
3. 내용 입력 후 **💾 저장**

> **💡 팁**: 상위 WBS 드롭다운에서 부모를 변경하면 계층 구조를 자유롭게 재구성할 수 있습니다.

### 3-4. WBS 수정

WBS 카드의 **✏️** 버튼 → 수정 폼 표시 → 수정 후 **💾 저장**

### 3-5. WBS 삭제

WBS 카드의 **🗑️** 버튼 클릭

> **⚠️ 주의**: 해당 WBS의 **모든 하위 WBS**와 **연결된 Action Item**도 함께 삭제됩니다.

### 3-6. 진척률 롤업

#### 개별 WBS 롤업
WBS 카드의 **📊** 버튼 → 해당 WBS 하위의 진척률을 재계산하여 현재 WBS에 반영

#### 전체 롤업
툴바의 **🔄 전체 롤업** 버튼 → 모든 WBS를 하위부터 상위 순으로 재계산

**롤업 알고리즘**:
- **리프 노드** (하위 WBS 없음): 연결된 Action Item의 완료 비율 (없으면 수동 진척률 사용)
- **부모 노드**: 활성(취소 제외) 자식 WBS들의 평균 진척률

```
예시:
Sub WBS 1.1: Action 3건 중 2건 완료 → 67%
Sub WBS 1.2: Action 5건 중 5건 완료 → 100%
Main WBS 1.0: (67 + 100) / 2 = 84%
```

## 4. ✅ Action Items 탭

### 4-1. Action Item 구조

Action Item은 WBS에 귀속되거나, 독립적으로 존재할 수 있습니다.

```
WBS 귀속 Action:
  📂 Main WBS 1.0
    └ 🔗 Action: 프로세스 설계서 작성 (문서작성, in_progress)
    └ 🔗 Action: SAP SD 설정 완료 (개발, todo)

독립 Action (WBS 미배정):
  📌 Action: 팀 킥오프 미팅 (미팅, done)
```

### 4-2. Action Item 조회 및 필터

| 필터 | 설명 |
|------|------|
| 유형 | Action 유형별 필터 (마스터 데이터 기준) |
| 상태 | 대기/진행중/완료/블록 필터 |
| WBS 필터 | 특정 WBS 귀속 Action 조회, "📌 WBS 미배정" 선택 시 독립 Action만 표시 |
| 🔍 검색 | 내용(content)에서 키워드 검색 |

**전체 보기 시**: 화면 상단에 WBS 미배정 Action이 별도 섹션으로 먼저 표시됩니다.

### 4-3. Action Item 추가

1. 우측 **➕ Action 추가** 버튼 클릭
2. 폼에서 입력:

   **① WBS 귀속 설정** (가장 중요, 최상단 표시)
   - WBS를 선택하면 해당 WBS의 현재 Action 통계가 미리보기로 표시
   - "⬜ 귀속 WBS 없음 (독립 Action)" 선택 시 독립 Action으로 분류

   **② 유형 & 상태**
   - Action 유형: 마스터에서 선택
   - 상태: 대기/진행중/완료/블록

   **③ 내용**: 수행할 구체적인 내용 입력

   **④ 날짜**: 시작일, 종료예정일, 종료일

3. **💾 저장** 클릭

> **💡 완료 저장 시**: "완료 저장 시 귀속 WBS의 자동 진척률이 변경됩니다" 안내가 표시됩니다. WBS 탭에서 📊 버튼을 눌러야 반영됩니다.

### 4-4. Action Item 수정

각 Action 카드를 펼쳐서 **✏️** 버튼 → 수정 폼 → 저장

### 4-5. Action Item 삭제

각 Action 카드의 **🗑️** 버튼 클릭

### 4-6. 마감 기한 표시

| 표시 | 의미 |
|------|------|
| `⏰ N일 초과` (빨강) | 마감일 초과 |
| `⏰ D-N` (주황) | 3일 이내 마감 |
| `📅 D-N` (노랑) | 7일 이내 마감 |
| `📅 D-N` (회색) | 7일 초과 |

## 5. 📤 노트 업로드 탭 (Obsidian 연동)

이 탭은 **Obsidian**과의 연동을 지원합니다. 3가지 방법으로 데이터를 입력할 수 있습니다.

### 5-1. 빈 템플릿 다운로드

3가지 Obsidian 템플릿을 제공합니다:

| 템플릿 | 설명 | 파일명 |
|--------|------|--------|
| 📋 WBS 항목 템플릿 | WBS 계층 항목 작성용 | `WBS_Template.md` |
| ✅ Action Item 템플릿 | 개별 Task/Action 작성용 | `ActionItem_Template.md` |
| 📝 회의록 템플릿 | 회의록 겸 Action 추출용 | `Meeting_Template.md` |

**사용법**:
1. 해당 템플릿의 **⬇️ 빈 템플릿 다운로드** 클릭
2. 다운로드된 `.md` 파일을 Obsidian Vault에 저장
3. Obsidian에서 파일을 열어 YAML frontmatter와 본문 편집
4. 완성된 파일을 다시 이 탭에서 업로드

### 5-2. 마법사(Wizard)로 작성

단계별 안내를 따라 빠르게 노트를 작성하는 방법입니다.

#### WBS 마법사 (8단계)

**📋 WBS 마법사로 작성** 버튼 클릭 → 팝업 다이얼로그에서 진행

| 단계 | 입력 항목 | 입력 유형 |
|------|----------|----------|
| 1 | WBS 코드 (예: 1.1) | 텍스트 (Enter로 건너뜀 가능) |
| 2 | 카테고리 | 드롭다운 |
| 3 | 항목 유형 | 카테고리 연동 드롭다운 |
| 4 | 담당자 | 텍스트 |
| 5 | 시작일 | 날짜 선택 |
| 6 | 종료예정일 | 날짜 선택 |
| 7 | 일정 상태 | 드롭다운 |
| 8 | 상세 내용 | 텍스트 영역 |

완료 후:
- **⬇️ .md 다운로드**: Obsidian에서 계속 편집할 수 있는 파일 다운로드
- **💾 DB에 WBS 저장**: 즉시 DB에 저장 (wbs_code로 부모 자동 탐색)
- **🔄 다시 작성**: 처음부터 다시

#### Action Item 마법사 (7단계)

**✅ Action 마법사로 작성** 버튼 클릭

| 단계 | 입력 항목 | 입력 유형 |
|------|----------|----------|
| 1 | 액션 유형 | 드롭다운 |
| 2 | 귀속 WBS | WBS 계층 선택기 |
| 3 | 담당자 | 텍스트 |
| 4 | 시작일 | 날짜 선택 |
| 5 | 종료예정일 | 날짜 선택 |
| 6 | 현재 상태 | 드롭다운 |
| 7 | 할 일 내용 | 텍스트 영역 |

### 5-3. 마크다운 파일 업로드

작성한 `.md` 파일을 직접 업로드하여 DB에 저장합니다.

**절차**:
1. **마크다운 파일 선택** 영역에서 `.md` 파일 선택 (복수 선택 가능)
2. 파싱 결과 미리보기 확인
   - ✅: 파싱 성공 (WBS 또는 action_item 인식)
   - ⚠️: 파싱 실패 (type 필드 없거나 잘못된 경우)
3. **⬇️ N개 항목 가져오기** 클릭 → DB 저장

**WBS 노트 필수 YAML**:
```yaml
---
type: wbs                     # ← 필수! "wbs"여야 함
wbs_code: "1.1"
wbs_category: "To be process 개발"
wbs_type: "process 체계도"
status: scheduled
start_date: "2025-06-01"
due_date: "2025-06-30"
---
```

**Action Item 노트 필수 YAML**:
```yaml
---
type: action_item             # ← 필수! "action_item"이어야 함
action_type: "문서작성"
status: todo
due_date: "2025-06-15"
wbs_ref: "1.1"                # 귀속 WBS 코드 (선택)
---
```

### 5-4. AI 자유 노트 분석

구조화되지 않은 메모에서 Action Item을 AI로 자동 추출합니다.

1. **자유 형식 노트 붙여넣기** 영역에 텍스트 입력 (회의 내용, 현장 메모 등)
2. **🔍 AI로 Action Item 추출** 클릭
3. 추출된 항목 확인
4. **📥 전체 저장** 클릭

> **⚠️ 주의**: LLM 설정이 필요합니다. ⚙️ 시스템/데이터 관리 탭에서 API 키를 먼저 설정하세요.

### 5-5. YAML 스키마 참조

탭 내 **📖 YAML Frontmatter 스키마 참조** 섹션(펼치기)에서 전체 스키마를 확인할 수 있습니다.

## 6. 📊 Gantt & 대시보드 탭

### 6-1. 차트 대시보드 (📈)

4개의 Plotly 차트를 제공합니다:

| 차트 | 설명 |
|------|------|
| WBS 상태 도넛 | 전체 WBS의 상태 비율 (대기/진행중/완료/블록) |
| Action 상태 도넛 | 전체 Action의 상태 비율 |
| WBS 진척률 막대 | 항목별 진척률 수평 바 (상위 12개, 상태색 반영) |
| 월별 등록 현황 | 월별 WBS 등록 건수 스택 바 |

### 6-2. Gantt 차트 (🗂️)

**보기 선택**: `WBS` 또는 `Action Items` 라디오 버튼으로 전환

**Gantt 차트 특징**:
- **오늘 날짜**: 빨간 점선으로 표시
- **진척률 오버레이**: 초록색으로 완료된 비율 시각화
- **상태 색상**: 대기(회색), 진행중(주황), 완료(초록), 블록(빨강)
- **호버 정보**: 마우스 오버 시 시작일, 마감일, 상태, 진척률 표시
- **표시 조건**: 시작일 + 종료예정일이 모두 입력된 항목만 표시

> **💡 팁**: Gantt 차트에 항목이 표시되지 않는다면 WBS/Action에서 **시작일**과 **종료예정일**을 입력했는지 확인하세요.

## 7. 🤖 AI 에이전트 탭

ERP 프로젝트 전문 AI 어시스턴트와 대화할 수 있습니다.

### 7-1. 빠른 실행 버튼

| 버튼 | 기능 |
|------|------|
| 📋 현황 분석 요청 | 전체 프로젝트 현황 분석 + 위험요소 + 권고사항 |
| ⚠️ 마감 임박 알림 | 마감 임박/초과 항목 우선순위 처리 전략 |
| 📝 전략 보고서 생성 | 현황 기반 5섹션 전략 보고서 (현황요약/리스크/Action Plan/중기권고/체크리스트) |

### 7-2. 자유 질문

하단 채팅 입력창에서 자유롭게 질문할 수 있습니다.

**활용 예시**:
```
Q: SAP SD 모듈에서 Fit-Gap 분석 방법을 알려줘
Q: 현재 블록된 WBS 항목들의 처리 방법은?
Q: RAP 프로그래밍에서 CDS View 최적화 방법은?
Q: 프로세스 체계도 작성 시 고려해야 할 사항은?
```

### 7-3. AI 컨텍스트

AI는 항상 **현재 DB 데이터**를 컨텍스트로 받습니다:
- WBS/Action 통계 (총계, 완료, 진행중)
- 진행중/블록 WBS 목록
- 마감 초과 Action 목록

### 7-4. 대화 초기화

**🗑️ 대화 초기화** 버튼으로 채팅 히스토리 삭제

> **⚠️ 주의**: LLM 설정(API 키 또는 로컬 LLM URL)이 없으면 경고가 표시되며 AI 기능이 동작하지 않습니다.

## 8. ⚙️ 시스템/데이터 관리 탭

### 8-1. WBS 항목 유형 관리 (📂)

WBS 폼에서 사용할 카테고리와 유형을 관리합니다.

**유형 추가**:
1. 카테고리 선택 (기존) 또는 "+ 신규 카테고리" 선택 후 이름 입력
2. 새 항목 유형명 입력
3. ➕ 추가 버튼

**유형 삭제**: 목록에서 해당 항목의 🗑️ 버튼

> **⚠️ 주의**: 이미 WBS 항목에서 사용 중인 유형을 삭제해도 기존 데이터는 유지됩니다.

### 8-2. Action Item 유형 관리 (🏷️)

Action 폼에서 사용할 유형을 관리합니다.

**유형 추가**: 유형명 입력 → ➕ 추가  
**유형 삭제**: 목록의 🗑️ 버튼

### 8-3. LLM 설정 (🔑)

AI 에이전트, 음성 분석, 자유 노트 분석에 사용되는 LLM을 설정합니다.

| 필드 | 설명 |
|------|------|
| API Key | OpenAI API 키 (`sk-...`) |
| Base URL | 로컬 LLM URL (예: `http://localhost:11434/v1`) |
| 모델명 | 사용할 모델 (예: `gpt-4o-mini`, `llama3`) |

**💾 설정 저장** 클릭 후 즉시 적용

> 설정은 DB의 `llm_settings` 테이블에 저장되므로 앱 재시작 후에도 유지됩니다.

## 9. 음성 메모 기능 (Voice Memo)

> **사전 요구사항**: `faster-whisper`, `ffmpeg-python` 패키지 + `ffmpeg` 시스템 도구 필요

음성 메모 기능은 **📤 노트 업로드** 탭 내에서 접근합니다 (Voice Memo 섹션).

### 9-1. 업로드 지원 형식

| 형식 | 직접 처리 | ffmpeg 변환 |
|------|----------|------------|
| WAV | ✓ | - |
| MP3 | - | ✓ |
| M4A | - | ✓ (iPhone 녹음) |
| OGG | - | ✓ |

### 9-2. STT 변환

1. 음성 파일 업로드
2. **모델 크기** 선택:
   - `tiny`: 가장 빠름, 정확도 낮음
   - `small` (기본): 균형 잡힌 속도/정확도
   - `medium`: 높은 정확도
   - `large`: 최고 정확도, 시간 오래 걸림
3. **🎙️ STT 변환 시작** 클릭
4. 변환된 텍스트와 타임스탬프 구간 확인

### 9-3. AI 분석 및 WBS/Action 매칭

1. STT 완료 후 **🤖 AI 분석** 클릭
2. 분석 결과 확인:
   - **요약**: 미팅/메모 2~4줄 요약
   - **참석자**: 자동 추출
   - **WBS 후보**: 언급된 WBS 항목 (신뢰도 high/medium/none)
   - **Action 후보**: 할 일 목록 (담당자, 기한 포함)
3. 기존 WBS와 매칭된 항목 확인
4. **저장** 버튼으로 선택 항목 DB 저장

### 9-4. 회의록 자동 생성

분석 결과를 Obsidian 회의록 형식 `.md`로 다운로드할 수 있습니다.

## 11. 자주 묻는 질문 (FAQ)

**Q: Gantt 차트에 항목이 표시되지 않아요.**  
A: WBS 또는 Action Item에 **시작일**과 **종료예정일**이 모두 입력되어야 합니다.

**Q: 진척률이 업데이트되지 않아요.**  
A: WBS 탭에서 **📊** (개별) 또는 **🔄 전체 롤업** 버튼을 클릭하세요. Action 상태 변경은 자동으로 반영되지 않으며, 수동으로 롤업을 실행해야 합니다.

**Q: Obsidian 노트 업로드 시 "인식불가"가 표시돼요.**  
A: YAML frontmatter의 `type` 필드가 정확히 `wbs` 또는 `action_item`이어야 합니다. YAML 블록은 `---`로 시작하고 `---`로 끝나야 합니다.

**Q: AI 분석이 동작하지 않아요.**  
A: ⚙️ 시스템/데이터 관리 탭 > LLM 설정에서 API 키 또는 로컬 LLM URL을 설정하세요.

**Q: 음성 변환이 안 돼요.**  
A: `faster-whisper`와 `ffmpeg`가 설치되어 있는지 확인하세요.
```bash
pip install faster-whisper ffmpeg-python
brew install ffmpeg
```

**Q: WBS를 삭제했는데 Action Item도 사라졌어요.**  
A: WBS 삭제 시 해당 WBS에 귀속된 Action Item도 함께 삭제됩니다. 독립 Action으로 먼저 분리한 후 삭제하세요.

**Q: 포트를 변경하고 싶어요.**  
A: `./restart.sh [포트번호]`로 실행하세요. 예) `./restart.sh 8888`

**Q: 앱이 응답하지 않아요.**  
A: `./restart.sh`를 실행하면 기존 프로세스를 종료하고 재시작합니다.

**Q: wbs_ref를 설정했는데 Action이 WBS에 자동 귀속되지 않아요.**  
A: 현재 파일 업로드 시 `wbs_ref`로 자동 귀속은 미구현 상태입니다. 업로드 후 Action Items 탭에서 수동으로 WBS를 연결해 주세요.
